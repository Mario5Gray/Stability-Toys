# S4.2 JSON diagnostics implementation plan

Issue: `STABL-wzfgcsse`. Base: merged `main` at `9257cfb` (PR #107).
Planning: Sigma. Execution: Theta. Operator and review authority: Mario.
Status: proposed for review. Theta claims S4.2 only after the plan merges.

**Goal:** Make one `st-vector-map --json` result report measured SVG complexity,
actionable warnings, and distinct conversion, CAD, and print evidence states. Keep
the reviewed raster error measurements in the S4.1 corpus JSON.

**Architecture:** Reuse `SvgMetrics` and the normalized SVGs already held by the
conversion path. Recount a layer after CAD pinch repair because that repair can
insert vertices. Build result counts in `scripts/vector_map.py` after successful
publication; leave the manifest as the artifact authority. Add near-limit warnings
from measured per-layer metrics. The CLI does not render CAD, slice, print, or run
`resvg-py` for fidelity. The S4.1 corpus probe remains the producer of measured
mask-to-SVG error and CAD evidence.

**Tech stack:** Python 3.12, VTracer 0.6.15, pytest, the existing SVG inspector,
S4.1 corpus probe, and OpenSCAD 2021.01 for CAD regression checks.

## Contract and decisions

1. Keep result `schema_version: 1`, the current five top-level keys, exit codes,
   and `status` values. Add one top-level `evidence` key. Do not change `st gen
   --json`. Update exact-key tests deliberately.
2. On successful conversion, `counts` contains `layers`, `paths`, `commands`,
   `vertices`, `svg_bytes`, and `by_layer`. Each `by_layer` entry has `paths`,
   `commands`, `vertices`, and `svg_bytes`. `svg_bytes` is the UTF-8 size of the
   **published** SVG: the combined file at top level and each normalized layer
   file by role. Reinspect the final layer after a successful CAD pinch repair;
   the current repair updates only its byte count and can leave path-command
   metrics stale. Preserve the original upstream `raw_bytes` in the manifest
   while replacing final SVG complexity metrics. A standalone run uses the role `standalone`. Empty selected
   optional roles have no published SVG and no `by_layer` entry; their existing
   `role_empty` diagnostic remains visible. `vertices` counts coordinate points
   from M and L commands in the accepted polygon dialect, including points in
   retained degenerate subpaths. Z closes a subpath but adds no vertex. Top-level
   path, command, and vertex totals are sums of the published layers. Do not
   count the combined SVG twice.
3. Failure and invalid results keep zero counts and `by_layer: {}`. No result
   claims partially converted layers or success before a completion manifest is
   published. Preserve the existing single JSON object on stdout and diagnostic
   text on stderr.
4. `evidence` has exactly three independent states:
   `conversion: converted|failed|invalid`, `cad_render: not_run`, and
   `physical_print: pending`. The CLI never turns CAD or print to passed.
   The S4.1 corpus record may separately report a real CAD result; S4.5 owns
   slicer and physical evidence. `status: converted` still means SVG publication.

   A successful layered result has this additive shape (numbers and paths below
   are illustrative):

   ```json
   {
     "schema_version": 1,
     "status": "converted",
     "artifacts": {"svg": "out.svg", "manifest": "out.vector.json"},
     "counts": {
       "layers": 2, "paths": 14, "commands": 474, "vertices": 450,
       "svg_bytes": 4291,
       "by_layer": {
         "silhouette": {"paths": 6, "commands": 156, "vertices": 148, "svg_bytes": 1590},
         "structure": {"paths": 8, "commands": 318, "vertices": 302, "svg_bytes": 2809}
       }
     },
     "diagnostics": [],
     "evidence": {"conversion": "converted", "cad_render": "not_run", "physical_print": "pending"}
   }
   ```
5. Existing warnings (`thin_material`, `thin_background`,
   `requested_width_below_four_pixels`, `role_empty`, `multiple_solids`, and CAD
   geometry warnings) retain their codes and conditions. Add `limit_near_miss`
   only for a published layer when a measured value is at least 90% of, and no
   greater than, a configured **per-layer** policy limit. Check paths, commands,
   and the larger of raw and final published UTF-8 SVG bytes. Use integer comparison
   `10 * value >= 9 * limit`; do not round a ratio. Emit one warning per
   role/metric in role order. Fields: `level`, `code`, `role`, `metric`, `value`,
   `limit`, `message`. The combined SVG has no enforced path/command/byte cap,
   so its counts are informational and do not trigger this warning. Existing
   over-limit errors and output refusal remain unchanged.
6. The S4.1 `result.json` files and `index.json` already record fidelity per
   case/mode at the reviewed mask's processing resolution using locked S1.4
   tolerances. Keep these files and their FAIL verdicts intact. In particular,
   bracket, brick, gravel, and horse stay named failures under Mario's release
   ruling. S4.2 adds a regression check and documentation linking the CLI's
   counts and warnings to those per-case records; it does not add a reference
   mask CLI flag or make normal conversion depend on `resvg-py`.
   Adding `vertices` to new manifests changes their JSON bytes and hashes.
   Treat the committed S4.1 manifests as historical records from PR #107;
   compare measured geometry and pinned failure names when checking S4.2,
   not a newly generated manifest hash against the old one. S4.3 owns future
   repeatability evidence for the new output schema.
7. S4.1 evidence was produced with OpenSCAD 2021.01. Every S4.2 command that
   exercises CAD must set `OPENSCAD` explicitly and check `--version` first.
   Do not run a corpus evidence generation command with an unpinned `openscad`
   from `PATH`. A snapshot renderer re-baseline is a separate decision. Do not
   rewrite the committed S4.1 bundles or report as part of S4.2.
8. Existing child `STABL-wuzmvgxm` is later topology-fallback research. It is
   outside these diagnostics tasks and does not change the four known FAIL
   verdicts in this plan.
