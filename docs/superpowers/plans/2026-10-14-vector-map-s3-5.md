# S3.5 relief-0.4 preset plan

Issue: `STABL-mknlfcui`. Parent: `STABL-gqgxdbjl`. Base: merged `main` at `5b64cb7`.
Status: cold planning draft. Mario rules on the gates below, merges the plan, then assigns implementation.
Design: [vector-map relief design](../specs/2026-09-06-vector-map-relief-design.md), sections 5, 7, and 11.3.
Sprint plan: [Sprint 3](2026-10-08-vector-map-sprint-3.md), decision 5 and S3.5.
Prerequisite: S3.4 `STABL-gorlibrt` merged at `5b64cb7`. Its relief contract publishes `preset: null`, and the
entry point already passes an empty preset layer to `config.resolve(config.DEFAULTS, {}, recipe, cli)`.

## Goal and stop line

One named fabrication preset, `relief-0.4`, selected explicitly with `--preset relief-0.4` or a recipe
`preset` field. It fills the preset precedence slot that S3.4 left empty: built-in defaults, preset, recipe,
explicit CLI. It carries fabrication values only: silhouette thickness S = 1.2 mm, nominal structure width
0.8 mm, structure height H = 0.6 mm, nominal detail width 0.5 mm, detail height or depth D = 0.2 mm, backing
disabled. Every value stays overridable by recipe and CLI. The resolved values reach the manifest and the
layered replay recipe, and the manifest `relief.preset` names the preset.

Stop at review-ready S3.5. No second preset, no preset-supplied VTracer or Canny values, no change to the
S1.4 fitting defaults, no mesh render or CAD acceptance (S3.6), no print-suitability claim, and no geometry
change in the S3.4 source builder. A run without a preset keeps today's behavior exactly, including
`relief.preset: null`.

## Gates before implementation

Mario rules on these five points. Each has a proposed answer; the plan assumes the proposal until ruled
otherwise.

1. **A preset requires an export.** Proposed: an effective `--preset` or recipe `preset` with no effective
   `export_scad` exits 2, naming the missing export. The preset describes the SCAD source; with no source its
   values are dormant, and the existing dormant-value rule already rejects operator-supplied dormant values.
   A preset run without export would otherwise need an exception that weakens that rule.
   The S3.4 opt-out stays intact: an explicit `--no-export-scad` over a recipe export request validates every
   value and writes no SCAD, with a preset in place.
2. **The preset never decides role selection.** Proposed: the preset contributes a role width or a role height
   only when that role is in the selection. `--layers silhouette --preset relief-0.4 --export-scad` is valid:
   it publishes silhouette only, and structure and detail heights stay null. Without this rule a preset would
   trip two existing checks, `HEIGHT_ROLES` in `_relief()` ("structure_height_mm was given, but structure is
   not selected") and the role admission in `_role_requests()` ("structure settings were given, but structure
   is not selected"). The operator did not supply those values, so neither is an operator error.
3. **Preset field set.** Proposed: the preset supplies `silhouette_thickness_mm`, `structure_height_mm`,
   `detail_height_mm`, `backing_mm`, `structure.width_mm`, and `detail.width_mm`. It supplies no
   `export_scad`, `center`, `detail_mode`, `vtracer`, Canny control, or role source. A preset run therefore
   keeps detail mode `raised`, centering off, and the S1.4 fitting defaults. Confirm that the two nominal band
   widths belong to this task: they change raster preparation width, not the SCAD source, and their
   low-width warnings still come from the existing four-pixel rule.
4. **CLI override surface.** Proposed: `--preset` takes one known name; an unknown name exits 2 and names
   `relief-0.4` as the only preset. `--preset` replaces a recipe `preset`, because the CLI is the last layer.
   No `--no-preset` exists, matching the Sprint 3 decision that a recipe preset cannot be cleared from the
   CLI while `relief-0.4` is the only preset. The name matches exactly, with no case folding or aliases.
5. **Manifest and replay.** Proposed: `relief.preset` holds the preset name, or null when none was selected.
   The layered replay recipe gains `preset` and the seven resolved relief values, so a replay reproduces the
   run without the operator repeating flags. Role widths stay out of the replay recipe: replay consumes the
   saved prepared masks and never expands bands again, as `layered_debug_files` already records.

## Preset contents and precedence

| Field | Value | Kind |
|---|---|---|
| `silhouette_thickness_mm` | 1.2 mm | Relief number, S |
| `structure.width_mm` | 0.8 mm | Nominal structure band width, used in raster preparation |
| `structure_height_mm` | 0.6 mm | Relief number, H |
| `detail.width_mm` | 0.5 mm | Nominal detail band width, used in raster preparation |
| `detail_height_mm` | 0.2 mm | Relief number, D |
| `backing_mm` | 0.0 | Disabled backing |

Resolution rules:

- The preset layer is built only when a preset is selected. Without a selection the layer is `{}`, exactly as
  the entry point passes it today.
- Layers merge in order, so a recipe value replaces a preset value field by field, and an explicit CLI value
  replaces both. `--silhouette-thickness-mm 1.5` with `--preset relief-0.4` yields S = 1.5 mm.
- A preset supplies only the fields above. `--no-export-scad`, `--no-center`, and `--detail-mode raised` behave
  as they do now, since the preset sets none of them.
- Merged values pass through the existing relief checks. The preset values are valid on their own: D < S for
  engraving holds, and backing stays zero or positive.
- The preset carries no VTracer control and no Canny threshold or blur. Fitting defaults come from S1.4 and
  stay unchanged.
- `--preset relief-0.4 --detail-mode engraved` is valid with no special case: 0.2 mm is above zero and below
  1.2 mm.
- Precedence is unchanged for every non-preset field. The preset never sets `input`, `input_kind`,
  `width_mm`, `height_mm`, `layers`, or a role source.

## Admission and interaction rules

- A preset needs `input_kind image` with an explicit selection that includes silhouette. Standalone mask and
  edge modes reject `--preset` with exit 2, on the same rule that already rejects `--export-scad` and relief
  settings there.
- An image run without explicit layers rejects a preset with exit 2, naming the missing selection.
- A preset with effective export requires a positive silhouette thickness after resolution. Because the preset
  supplies one, only an explicit override to zero or a recipe clearing it can fail that check.
- Slot assignment is untouched: silhouette records S with mode `base`, structure records H with mode `raised`,
  and detail records D with mode `raised` or `engraved`.
- Warning behavior is untouched. Multiple-solids, thin-material, feature-coverage, and low-width warnings keep
  their current triggers and text.
- No implicit preset exists. A layered export run without a preset and without heights still exits 2 with
  "SCAD export requires a positive silhouette_thickness_mm", and a run without export still publishes
  `relief.preset: null`.

## Manifest, result and replay recipe

`Settings` gains `preset: str | None = None`, and the resolved relief mapping from `_relief()` in
`vector_map_config.py` carries it. `relief.preset` in the layered manifest reports the name, or null.

The layered replay recipe gains `preset` and the seven resolved relief fields: `export_scad`, `center`,
`detail_mode`, `backing_mm`, `silhouette_thickness_mm`, `structure_height_mm`, and `detail_height_mm`. A replay
of that recipe resolves to the same values through the normal precedence chain, because the recipe layer sits
above the preset layer and the recorded values equal the resolved ones.

Unchanged: schema version 1, the standalone manifest shape, the standalone result shape, `artifacts.scad` and
its hash, the fixed SCAD ownership rules, and the manifest-last publication. The result JSON gains no field.

## Documentation

`scripts/USAGE.md` is the only operator surface. It gains `--preset` in the flags table, the preset table, the
explicit-selection requirement, the override order, and the recorded manifest and replay fields. It replaces
the sentence that `preset` stays null until a later release. It states that the preset describes fabrication
settings only, that its values do not guarantee suitability for a given 0.4 mm nozzle, extrusion width,
material, or slicer configuration, and that suitability needs separate evidence. It states that fitting
defaults come from S1.4, not the preset.

Two code comments that name S3.5 as pending are updated: the entry-point note beside the empty preset layer,
and the `_relief()` docstring in `vector_map_artifacts.py`. Merged plan documents stay as written; the S3.4
plan is a historical record and is not edited.
