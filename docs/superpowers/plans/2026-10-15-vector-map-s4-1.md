## Decisions for review

1. **Case verdict.** Run `metrics.evaluate()` on the published silhouette SVG rendered at the
   reviewed mask's processing size. All eight checks in its `checks` map block the fidelity
   verdict: area, topology, bounds, scale, centroid, orientation, XOR, and boundary. (The shape
   mismatch path also fails scale.) Use the existing values in `metrics.TOLERANCES`: topology
   exact; bounds and box size 1 px; centroid 0.5 px; XOR/perimeter 0.5 px; boundary maximum
   1.5 px; absolute polygon area error/perimeter 0.5 px. Orientation is strictly the lowest
   XOR. Do not replace these with a combined score. Conversion, artifact hashes, replay,
   preview, and native CAD each have separate checks. A case passes only if every required
   check passes. The probe exits nonzero when any case fails or required evidence is missing.
2. **Known small features.** The S1.4 sweep at `filter_speckle=4` pins bracket to centroid;
   brick to centroid and topology; gravel to boundary and topology; horse to centroid and
   topology. `tests/test_vector_map_corpus.py` records that no tested speckle value fixes
   these four. Keep them as per-case `FAIL`, not exemptions or aggregate passes. An S4.1
   evidence issue may reach review with those failures documented, but overall corpus
   acceptance and release readiness remain blocked. Name follow-up issue IDs before closing
   S4.1. Do not tune a global default or relax a tolerance to make these rows green.
3. **Defaults and recipes.** The shipped fitting default is VTracer polygon mode with
   `filter_speckle=4`; the image workflow has its own current Canny and raster defaults.
   `relief-0.4` is an opt-in fabrication preset, not an implicit shipped default.
   The primary case run uses `--preset relief-0.4` so native relief can render, while the
   resolved manifest records the actual fitting defaults. Assess those defaults explicitly
   with the S1.4 baseline and the new published-output measurements. A per-case change must
   be a recipe override with keys `case`, `baseline_recipe`, `override_recipe`, `changed_fields`,
   `reason`, `baseline_checks`, and `override_checks`. Record it in the S4.1 evidence JSON and
   save the executable recipe in that case's bundle. No silent per-case CLI tuning. A failed

4. **Detail mode.** Raised is the primary eight-case result. Run all eight engraved cases too,

## Measurement contract

Use each `tests/fixtures/vector_map/corpus/<case>/mask.png` as white material. Verify its SHA256
against `corpus.json` before conversion. Run `--input-kind image --mask <reviewed mask>
--width-mm 100 --layers silhouette,structure,detail --preset relief-0.4 --export-scad
--debug-bundle --preview`. Use source and destination as the first two positional arguments.
The primary recipe must preserve the actual resolved values in the manifest. Use the generated
debug recipe as the replay basis, not a hand-transcribed guess.

Render the **published** `out.layers/silhouette.svg` with resvg at the mask's processing width
and height. Its root declares millimetres. Supply `dpi = 25.4 / manifest.canvas.mm_per_px` so
the intrinsic raster size equals the processing size; `metrics.render()` alone lacks this DPI
and rejects a millimetre root. Keep its `crisp_edges`, white background, and `luma < 128` rule.
Run `metrics.evaluate(mask, rendered, metrics.polygon_area(svg))`. `polygon_area` is in px².
The CAD repair may move a ring by a fraction of a pixel, so measure the final published SVG,
not the raw VTracer trace. Save the rendered silhouette, the mask, and an XOR preview so the
numbers are visually inspectable. If a normalized SVG cannot be rendered with this documented
DPI on the locked renderer, record a failed fidelity row instead of substituting raw trace.

Record per-role SVG complexity as paths, subpaths, commands, and UTF-8 bytes. Record combined
SVG complexity separately. `metrics.svg_complexity()` accepts polygon paths and supported
translate transforms. If the combined SVG needs a different parser, count its paths and bytes
with XML and document the method. Never feed a millimetre area directly to a pixel metric.

Use S3.6's CAD gates for each mode: conversion exit, manifold diagnostics, XY/Z bounds,
solid count, genus, and volume with locked relative tolerance `1e-4`. Its volume expectation
uses OpenSCAD effective 2D areas, so it does not independently prove the 2D clip. Keep the
published-area figure and excess beside it. Require `filter_speckle >= 3` for the solid-count
rule; the corpus baseline is 4. If an override lowers it, do not assert the S3.6 count formula.
Instead record the CAD count as unresolved until a separately proved expectation exists.

Every case JSON has `case`, `mode`, `source_sha256`, `mask_sha256`, `argv`, `resolved_recipe`,
`manifest_sha256`, `artifact_hashes`, `fidelity` with each measured check and failure name,
`complexity`, `timings`, `cad` with expected and measured geometry, `override`, and `passed`.
The index lists all sixteen mode rows and an eight-case fidelity summary. Missing files,
missing hashes, missing render evidence, and unexpected exceptions produce explicit failed
rows. Never omit a case after one fails. Record host paths as provenance, not as required
stable bytes. Reproduction compares hashes of deterministic bundle artifacts and measured
verdicts; it does not require byte-identical STL or timing output across hosts.
