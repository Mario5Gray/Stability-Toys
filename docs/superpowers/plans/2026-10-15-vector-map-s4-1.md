## Decisions for review

1. **Case verdict.** Run `metrics.evaluate()` on the published silhouette SVG rendered at the
   reviewed mask's processing size. All eight checks in its `checks` map block the fidelity
   verdict: area, topology, bounds, scale, centroid, orientation, XOR, and boundary. (The shape
   mismatch path also fails scale.) Use the existing values in `metrics.TOLERANCES`: topology
   exact; bounds and box size 1 px; centroid 0.5 px; XOR/perimeter 0.5 px; boundary maximum
   1.5 px; absolute polygon area error/perimeter 0.5 px. Orientation is strictly the lowest
   XOR. Do not replace these with a combined score. Conversion, artifact hashes, replay,
   preview, and native CAD each have separate checks. Record `fidelity_passed` per case,
   `evidence_complete` for the run, and `release_accepted` separately. A case with a failed
   fidelity check remains `FAIL` even when its failure matches the pinned baseline. The probe
   exits 0 only when all evidence is complete, all CAD and artifact checks pass, and the eight
   fidelity failure-name sets exactly match the pinned S1.4 sets. An unexpected failure or a
   formerly failing case that now passes changes that signature and exits nonzero. This is a
   strict regression contract, not a claim of eight-case release acceptance.
2. **Known small features.** The S1.4 sweep at `filter_speckle=4` pins bracket to centroid;
   brick to centroid and topology; gravel to boundary and topology; horse to centroid and
   topology. `tests/test_vector_map_corpus.py` records that no tested speckle value fixes
   these four. Keep them as per-case `FAIL`, not exemptions or aggregate passes. An S4.1
   evidence issue may close with those failures documented, but its `release_accepted` value
   is false unless Mario explicitly accepts them as release limitations. The recommended
   release path is to document the four cases and their minimum-feature constraint in the
   operator guidance, then have Mario accept those limits. The alternative is a repair and
   re-run under `STABL-wuzmvgxm`. That S4.2 research issue currently starts after release or
   demand for sub-4-pixel geometry; making it a release blocker would change its scope and
   priority. The probe never makes that release decision. Do not tune a global default or
   relax a tolerance to make these rows green.
3. **Defaults and recipes.** The shipped fitting default is VTracer polygon mode with
   `filter_speckle=4`; the image workflow has its own current Canny and raster defaults.
   `relief-0.4` is an opt-in fabrication preset, not an implicit shipped default.
   The primary case run uses `--preset relief-0.4` so native relief can render, while the
   resolved manifest records the actual fitting defaults. Assess those defaults explicitly
   with the S1.4 baseline and the new published-output measurements. A per-case change must
   be a recipe override with keys `case`, `baseline_recipe`, `override_recipe`, `changed_fields`,
   `reason`, `baseline_checks`, and `override_checks`. Record it in the S4.1 evidence JSON and
   save the executable recipe in that case's bundle. No silent per-case CLI tuning. A failed
   case with no justified override has `override_recipe: null` and remains failed.
4. **Detail mode.** Raised is the primary eight-case result. Run all eight engraved cases too,
   using the same source, mask, and recipe except `detail_mode: engraved`. Fidelity is measured
   once per published silhouette because detail mode does not change that mask. Native CAD
   results stay distinct by mode. Missing detail layers remain valid and are recorded as such.
5. **Committed evidence.** Commit the report, one JSON index, and per-case directories with
   the resolved replay recipe, input provenance and hashes, prepared masks, combined and
   separate SVGs, raster and mesh preview PNGs, the generated `out.scad` and
   `out.vector.json` for each mode, and a result JSON. The reviewed source and mask PNGs
   already live under `tests/fixtures/vector_map/corpus/`; reference their paths and hashes
   instead of copying them again. Commit no STL files. Record STL hashes, OpenSCAD command
   and work path. Each intact mode bundle must let one OpenSCAD command rebuild its STL.
   Raised and engraved SVGs may be byte-identical. Keep their files in both mode directories
   if their original manifests name those relative paths. Deduplicating them by moving files
   would break the manifest path and the SCAD import contract. Check the actual repository
   size before committing and report it in review. The measured eight-case SVG and prepared
   mask set is about 692 KB per mode, so the intact pair is acceptable.
6. **Harness.** Add `tests/vector_map_s4_1_corpus_probe.py` rather than expanding the S3.6
   acceptance script. Import its `_vertices`, `_preview`, `_hashes`, and
   `verify_manifest_hashes` directly as test-harness helpers. Do not import its `_run_case`,
   which is tied to S3.6 scenes and verdicts. Do not move helpers into a shared module in
   this evidence task. Reuse
   `metrics.evaluate`, `svg_complexity`, `polygon_area`, and `TOLERANCES`. Reuse
   `tests/test_vector_map_openscad.py` executable discovery, work-directory handling, and
   mesh helpers. Keep the new blocking probe outside `test_*.py` collection. Collected unit
   tests use deterministic fixtures and may skip native OpenSCAD when absent. The explicit
   probe exits nonzero without OpenSCAD.
7. **Timings.** Record preparation/conversion, SVG rasterization and metrics, OpenSCAD render,
   and preview generation separately with `time.perf_counter()`. Record host OS, CPU, Python,
   VTracer, resvg and OpenSCAD versions. Use one untimed warm-up and five timed calls with the
   median for trace and SVG render, matching `metrics.TIMING`; use one timed full conversion and
   native render per case and mode, since each writes a distinct bundle. Timings are diagnostic.
   They cannot pass or fail a case. Do not compare absolute times across hosts.
8. **Slicer scope.** S4.1 records no slicer result or physical print result. S4.5 owns those.
9. **Baseline separation.** Run the focused and full suites, but name any failure by test and
   compare it to merged main before attributing it. The known `test_entry_spans` failure is
   `STABL-fjmjolci`. The CPU image packaging failure is `STABL-bxqlmcmf`. Neither changes
   a corpus row's fidelity or CAD verdict. New failures on touched paths block review.

## Measurement contract

Use each `tests/fixtures/vector_map/corpus/<case>/mask.png` as white material. Verify its SHA256
against `corpus.json` before conversion. Run `--input-kind image --mask <reviewed mask>
--width-mm 100 --layers silhouette,structure,detail --preset relief-0.4 --export-scad
--debug-bundle --preview`. Use source and destination as the first two positional arguments.
The primary recipe must preserve the actual resolved values in the manifest. Use the generated
debug recipe as the replay basis, not a hand-transcribed guess.

Render the **published** `out.layers/silhouette.svg` at the mask's processing width and height.
Its root declares millimetres, which `metrics.render()` rejects. For measurement only, copy
the SVG bytes in memory and replace root `width` and `height` with the viewBox pixel dimensions.
Keep the viewBox, paths, groups, transforms, and stored SVG unchanged. Then call
`metrics.render()` unchanged, preserving its locked `crisp_edges`, white background,
`luma < 128`, and one SVG unit per pixel rules. Do not set DPI. The reviewer measured an
11-pixel difference on coins with the proposed DPI method; root replacement gave zero
pixel difference against the locked raw-trace render. Run
`metrics.evaluate(mask, rendered, metrics.polygon_area(svg))`. `polygon_area` is in px².
Measure the published SVG because that is the released artifact. The eight published
silhouettes currently have the same area and raster as their raw traces; the CAD compatibility
repair does not change them. Save the rendered silhouette, mask, and XOR preview so the
numbers are visually inspectable. If root replacement does not preserve the viewBox or the
locked render, record a failed fidelity row rather than substituting the raw trace.

Record per-role SVG complexity as paths, subpaths, commands, and UTF-8 bytes. Record combined
SVG complexity separately. `metrics.svg_complexity()` accepts polygon paths and supported
translate transforms. If the combined SVG needs a different parser, count its paths and bytes
with XML and document the method. Never feed a millimetre area directly to a pixel metric.

Use S3.6's CAD gates for each mode: conversion exit, manifold diagnostics, XY/Z bounds,
solid count, genus, and volume with locked relative tolerance `1e-4`. Its volume expectation
uses OpenSCAD effective 2D areas, so it does not independently prove the 2D clip. Keep the
published-area figure and excess beside it. Require `filter_speckle >= 3` for the solid-count
rule; the corpus baseline is 4. If an override lowers it, do not assert the S3.6 count formula.
Instead record the CAD count as unresolved until a separately proved expectation exists.

Every case JSON has `case`, `mode`, `source_sha256`, `mask_sha256`, `argv`, `resolved_recipe`,
`manifest_sha256`, `artifact_hashes`, `fidelity` with each measured check and failure name,
`complexity`, `timings`, `cad` with expected and measured geometry, `override`,
`fidelity_passed`, and `cad_passed`. The index lists all sixteen mode rows, an eight-case
fidelity summary, `evidence_complete`, `fidelity_matches_pin`, and `release_accepted`.
`release_accepted` remains false for the four pinned failures until Mario records a separate
release ruling. Missing files,
missing hashes, missing render evidence, and unexpected exceptions produce explicit failed
rows. Never omit a case after one fails. Record host paths as provenance, not as required
stable bytes. Reproduction compares hashes of deterministic bundle artifacts and measured
verdicts; it does not require byte-identical STL or timing output across hosts.
