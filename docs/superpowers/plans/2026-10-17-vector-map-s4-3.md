## Decisions and boundaries

1. Recommend option 2 from `STABL-mlahbjjj`: a vector-only runtime guard for CPython >=3.14. `scripts/pyproject.toml` has one distribution-wide `requires-python`; a `<3.14` cap would also remove canny, depth, and pose. A later VTracer version has no accepted topology, OpenSCAD, or determinism evidence. Preserve the pin until a separate bump review passes. Record the option comparison and final policy in the S4.3 report and child issue. If review selects another option, revise this plan before code changes.
2. The known crash is documented in the child issue on Fedora 44 / CPython 3.14.7. Do **not** rerun unguarded `convert_raw_image_to_svg` in the main test process. A subprocess test may run the guarded adapter under real 3.14; require a normal nonzero exit, an actionable message, and no native crash. Simulated version tests prove guard ordering, not native-platform safety.
3. Distinguish *install allowed*, *tested*, and *supported*. Current release proof is CPython 3.12 on tested hosts. Mark 3.10, 3.11, and 3.13 unverified unless a real isolated run is recorded for each. Mark vector conversion on >=3.14 refused. Do not infer compatibility from a wheel's presence. Record platform and architecture beside every row.
4. `all` remains depth + pose + canny; vector remains separate. Vector and canny must run without Torch. Depth and pose need Torch and preserve their console commands. Follow the documented macOS Torch via conda setup where needed; do not treat an installation failure caused by missing platform prerequisites as a pass.
5. Run a *candidate* version-change exercise only in a disposable environment, without editing the production pin. Record the exact candidate, why it was selected, installed wheel, and S1.2 topology, S2.4 adapter, S1.3 CAD, and repeatability outcomes. The published [VTracer releases](https://pypi.org/project/vtracer/#history) include prereleases; do not silently promote one. If no suitable candidate can be installed, record the blocked experiment and keep the production pin. A future pin change needs its own review.
6. S4.1's 16 committed rows, four known fidelity failures, recipes, and historical hashes remain unchanged. S4.2 added vertices and evidence fields; compare newly generated runs to each other, not byte-for-byte against old S4.1 manifests. `physical_print` remains `pending` in CLI JSON despite the separate S4.5 [print report](../reports/2026-10-17-vector-map-s4-5-print-trial.md).
