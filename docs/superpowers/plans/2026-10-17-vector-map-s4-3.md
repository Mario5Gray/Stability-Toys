**Goal:** Establish a safe Python support policy, repeatable conversion evidence, and an honest installation matrix for the finished vector-map workflow.

**Architecture:** Keep `vtracer==0.6.15` pinned for production. Reject CPython >=3.14 in the CLI before bundle creation or raster preparation, with the same check in the vector adapter before importing VTracer. Leave the other extras installable. Run real conversion and isolated package installations, then record each result with interpreter, platform, dependency versions, commands, and artifacts. Keep the committed S4.1 rows as historical evidence.

**Tech stack:** Python 3.12 baseline, pytest, pip/venv, VTracer 0.6.15, resvg-py 0.5.0, and OpenSCAD 2021.01 for any CAD run.

## Decisions and boundaries

1. Select option 2 from `STABL-mlahbjjj`: a vector-only runtime guard for CPython >=3.14 at **both** entry points. In `scripts/vector_map.py`, call one adapter support-check function after `_settings` succeeds and before `Bundle` creation, `bundle.check`, input snapshots, renderer checks, and raster preparation. Keep the same function inside `trace_layer` before `import vtracer` for direct adapter callers. An unsupported interpreter is a runtime refusal: exit **1**, JSON `status: failed`, `evidence.conversion: failed`, zero counts, and no SVG, manifest, preview, or debug bundle. Stderr and the JSON error must say the interpreter is unsupported, without a `VTracer ... layer ...` prefix. Invalid arguments/configuration still exit 2 with `status: invalid`. `--help` still exits 0. The distribution-wide `requires-python` cannot cap just one extra; a `<3.14` cap would also remove canny, depth, and pose. Record the comparison with all three issue options in the S4.3 report and child issue. If review selects another option, revise this plan before code changes.
2. The confirmed 0.6.15 crash is documented on enigma, Fedora 44 / CPython 3.14.7 x86_64. The Mac arm64 3.14 refusal is precautionary until a native 0.6.15 crash is demonstrated there; do not describe it as a reproduced macOS crash. Do **not** rerun unguarded `convert_raw_image_to_svg` in the main test process. Run the guarded CLI and adapter under real 3.14 in subprocesses on both hosts; require ordinary exit 1, an actionable message, no artifacts, and no native crash. Simulated version tests prove guard ordering, not native-platform safety.
3. The required platform matrix covers this Mac arm64 and enigma Fedora 44 x86_64. On each, run CPython 3.12 for the five extras and CPython 3.14 for the production-vector refusal plus a canny control. The Mac has `/opt/homebrew/bin/python3.12` and `/opt/homebrew/bin/python3.14`; enigma has system 3.14.7 and a previously used uv 3.12.12. Recheck interpreter identities at execution. Distinguish *install allowed*, *tested*, and *supported*. Mark 3.10, 3.11, and 3.13 unverified unless a real isolated run is recorded for each. Mark production vector conversion on >=3.14 refused. Do not infer compatibility from a wheel's presence.
4. `all` remains depth + pose + canny; vector remains separate. Vector and canny must run without Torch. Depth and pose need Torch and preserve their console commands. Follow the documented macOS Torch via conda setup where needed; do not treat an installation failure caused by missing platform prerequisites as a pass.
5. Evaluate **`vtracer==1.0.0a4`** as option 3 in disposable environments on both hosts under CPython 3.14; also run it under CPython 3.12 for comparison. [PyPI identifies it as a prerelease with macOS ARM64 and Linux x86_64 wheels](https://pypi.org/project/vtracer/1.0.0a4/). First inspect its installed API and run a tiny conversion in a timed subprocess with `-X faulthandler`; a native crash must stay contained there. If the 0.6.15 adapter API is absent or incompatible, record that as a failed interface gate rather than silently rewriting production code. If the interface gate passes, run S1.2 topology, S2.4 adapter, S1.3 CAD, and repeatability fixtures; identify any tests that fail only because they deliberately assert the production 0.6.15 pin. Record the exact candidate wheel and every result. Do not promote a prerelease, edit the production pin, or weaken fixture tolerances in S4.3. A later pin change needs its own review.
6. S4.1's 16 committed rows, four known fidelity failures, recipes, and historical hashes remain unchanged. S4.2 added vertices and evidence fields; compare newly generated runs to each other, not byte-for-byte against old S4.1 manifests. `physical_print` remains `pending` in CLI JSON despite the separate S4.5 [print report](../reports/2026-10-17-vector-map-s4-5-print-trial.md).
