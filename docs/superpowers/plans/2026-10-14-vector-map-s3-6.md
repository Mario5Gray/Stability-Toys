## Goal and stop line

Produce acceptance evidence for the complete layered relief workflow against an actual OpenSCAD
executable. The deliverable is the evidence, the report that presents it, and the harness that produces
both. Every case records the executable version, the exact command, the output, and the measured mesh
against an expectation derived from the raster, not from the generated SCAD.

Stop at review-ready S3.6 evidence. This task adds no production behaviour: `scripts/vector_map*.py` is
unchanged except where a gate here explicitly says otherwise. A defect the acceptance run finds is filed as
its own FP issue with its evidence and is **not** fixed inside S3.6. No print validation (Sprint 4), no slicer
claim, no physical-sample claim, no new preset, no S1.4 tolerance relaxation, and no S4 work.

Two spec rules bind the whole task:

- Successful conversion does not prove a successful CAD render. Conversion evidence and CAD evidence are
  recorded separately (spec 7).
- Do not claim success from generated SCAD syntax or from a browser view alone (spec 10). Only a real
  OpenSCAD render counts.

## Gates

1. **Where the blocking acceptance lives.** Local integration checks may skip when the executable is absent
   (spec 10), but relief release acceptance requires an actual render. The two rules need two surfaces.
   Recommended: a probe script `tests/vector_map_s3_6_cad_probe.py` following the Q4 precedent. It is not
   named `test_*.py`, so `tests/run.py`'s `rglob('test_*.py')` and a bare `pytest tests/` never collect it,
   and it is invoked explicitly. When it is invoked and OpenSCAD is absent it exits non-zero with a blocking
   message, which is the sprint rule. The per-case geometry contracts stay as collected tests in
   `tests/test_vector_map_scad.py`, where an absent executable skips as it does today.
   The alternative, a collected `tests/test_vector_map_cad_acceptance.py` that hard-fails without OpenSCAD,
   turns the CPU test container red, because that image installs `scripts/` but no OpenSCAD.
2. **What CAD acceptance measures, and what it does not.** S3.6 measures CAD geometry: XY and Z bounds,
   connected solid count, genus per solid, Z support planes, and mesh volume against the raster expectation.
   It does not re-measure tracing fidelity — that is the S1.4 corpus row, and its four known minimum-feature
   stress cases (bracket, brick, gravel, horse) are recorded as S1.4 findings, not re-litigated here.
   Confirm that boundary. It decides whether a corpus case that traces poorly blocks S3.6.
3. **Corpus scope.** Every corpus case measured gets its own row, pass or fail, and no aggregate score hides
   one (sprint step 4). The question is whether CAD acceptance runs all eight corpus cases or only the
   reviewed subset. Recommended: all eight, in mask mode, plus image mode with an external `--mask` as the
   sprint's external-mask case, with a case whose layered inputs are degenerate recorded as a finding rather
   than dropped.
4. **Evidence format and what is committed.** Recommended: the report
   `docs/superpowers/reports/2026-10-14-vector-map-s3-6-cad-acceptance.md`, a machine-readable JSON evidence
   file, and preview PNGs in a sibling directory, following `2026-10-09-vector-map-s3-2-canny/`. STL meshes
   are not committed: they are large, regenerable from the committed SVGs and the recorded command, and the
   JSON already carries their measurements. Confirm, or say which artifacts should be committed instead.
5. **The installed-console proof.** Sprint step 5 requires installed console behaviour in a fresh venv from
   `./scripts[vector]`, because the local conda environment holds an older installed copy. Recommended: build
   the venv, run the installed `st-vector-map` over one corpus case and one `--preset relief-0.4` case, and
   record `pip show`-level versions, argv, exit codes, and artifact hashes. Confirm the venv is created from
   the merged tree at this branch's base and is deleted afterwards, and that its evidence is provenance only,
   not a second acceptance set.
6. **No production change, and the CPU container.** Confirm gate 2's boundary implies S3.6 may not touch
   `scripts/`. Confirm the container evidence is `docker compose -f docker-compose.test.yml run --rm test-unit`
   (BACKEND cpu, `python -m tests.run tests/ -- -v -m "not ws"`), that CAD cases are absent there by design
   because the image installs no OpenSCAD, and that baseline failures such as `STABL-fjmjolci` are separated

## Case matrix and expected geometry

Expectations come from the raster and the requested relief values, never from the SCAD text. The synthetic
scene is `tests/test_vector_map_scad.scene_files` on a 32 x 24 mm canvas; S3.4 measured the first four rows
and S3.6 re-measures them from the merged tree.

| Case | Settings | Expected mesh |
|---|---|---|
| Raised structure, backing on | S 2, H 1, D 0.5, raised, B 1 | Z planes `[0, 1, 3, 3.5, 4]`; XY bounds `[0,0]`–`[32,24]`; 1 solid; genus 0 |
| Engraved detail | S 2, H 1, D 0.5, engraved, B 0 | Z planes `[0, 1.5, 2, 3]`; XY bounds `[2,2]`–`[30,22]`; 1 solid; genus 0 |
| Backing off, two islands | silhouette of two components, B 0 | 2 solids, bounds spanning both, genus 0 each |
| Backing on, two islands | same silhouette, B 1 | 1 solid, XY bounds `[0,0]`–`[32,24]` |
| Silhouette with holes | donut silhouette, B 1 | 1 solid; total genus equals the hole count |
| Preset end to end | `--preset relief-0.4`, connected silhouette | Z planes `[0, 1.2, 1.4, 1.8]` from S 1.2, D 0.2, H 0.6 and B 0; bounds from the canvas; solids from raster connectivity |
| Corpus case, mask mode | reviewed corpus mask, `--input-kind mask` | bounds and component count from the mask, genus from mask holes |
| Corpus case, image mode with external mask | corpus source plus `--mask`, `--layers silhouette,structure,detail` | bounds from the canvas; per-role solids from each prepared mask |

The engraved row is the one that proves engraving cuts detail only. Its Z planes must contain the engraving
floor `B + S - D = 1.5`, the silhouette top `B + S = 2`, and the structure top `B + S + H = 3`, and nothing
above `3`. A plane below `1.5` would mean the engraving cut past its depth, and a missing plane at `3` would
mean a structure ridge was cut by detail it should have survived.

## Method

1. Build the layered bundle with the real CLI path, in process, one case at a time, into a work directory an
   OpenSCAD sandbox can read. Record the argv, the exit code, the result JSON, and the manifest relief object.
2. Save the selected masks, the combined SVG, each published layer SVG, the manifest, and the SCAD source per
   case, and hash them. Manifest hash verification is sprint step 7.
3. Render the SCAD with the real executable, capturing stdout, stderr, and its version. Parse the STL into
   unique vertices and triangles, then compute bounds, Z planes, connected solids, and genus per solid.
4. Compare the measured mesh with the row's expectation. A mismatch is a failed case with its numbers
   recorded, not an aggregate decrement.
5. Emit one JSON evidence document keyed by case, holding versions, argv, output, masks and hashes, the
   manifest relief object, the expected geometry, and the measured geometry.
6. Write the report from that JSON, one section per case, with the exact reproduce command at the top.

The probe reuses `tests/test_vector_map_openscad.py` helpers (`_openscad`, `choose_work_dir`, `sandbox_error`,
`mesh_components`) so the executable discovery, the Flatpak home-directory rule, and the genus computation
have one implementation.
