## Goal and stop line

Produce acceptance evidence for the complete layered relief workflow against an actual OpenSCAD
executable. The deliverable is the evidence, the report that presents it, and the harness that produces
both. Every case records the executable version, the exact command, the output, and the measured mesh
against an expectation derived from the raster, not from the generated SCAD.

Stop at review-ready S3.6 evidence. This task adds no production behaviour: no production Python module
changes at all, so `scripts/vector_map*.py` and every other module under `scripts/` stays as merged. The one
permitted `scripts/` edit is `scripts/USAGE.md`, and only to record the probe command as operator
documentation. A defect the acceptance run finds is filed as its own FP issue with its evidence and is
**not** fixed inside S3.6. No print validation (Sprint 4), no slicer claim, no physical-sample claim, no new
preset, no S1.4 tolerance relaxation, and no S4 work.

Two spec rules bind the whole task:

- Successful conversion does not prove a successful CAD render. Conversion evidence and CAD evidence are
  recorded separately (spec 7).
- Do not claim success from generated SCAD syntax or from a browser view alone (spec 10). Only a real
  OpenSCAD render counts.

## Case matrix and expected geometry

Expectations come from the raster and the requested relief values, never from the SCAD text. The synthetic
scene is `tests/test_vector_map_scad.scene_files` on a 32 x 24 mm canvas; S3.4 measured the first four rows
and S3.6 re-measures them from the merged tree.

| Case | Settings | Expected mesh |
|---|---|---|
| Raised structure, backing on | S 2, H 1, D 0.5, raised, B 1 | Z planes `[0, 1, 3, 3.5, 4]`; XY bounds `[0,0]`–`[32,24]`; 1 solid; genus 0 |
| Engraved detail | S 2, H 1, D 0.5, engraved, B 0 | Z planes `[0, 1.5, 2, 3]`; XY bounds `[2,2]`–`[30,22]`; 1 solid; genus 0 |
| Backing off, two islands | silhouette of two components, B 0 | 2 solids, bounds spanning both, genus 0 each |
| Backing on, two islands | same silhouette, B 1 | 1 solid, XY bounds `[0,0]`–`[32,24]` |
| Through-hole, open | donut silhouette, B 0 | 1 solid; total genus 1 |
| Through-hole, filled | same donut silhouette, B 1 | 1 solid; genus 0, because a full rectangular backing fills the hole |
| Preset end to end | `--preset relief-0.4`, connected silhouette | Z planes `[0, 1.2, 1.4, 1.8]` from S 1.2, D 0.2, H 0.6 and B 0; XY bounds from the silhouette mask, not the canvas, because B 0 means no backing rectangle spans the canvas; solids from raster connectivity |
| Corpus case, image mode with external mask | corpus `source.png` plus `--mask` corpus `mask.png`, `--layers silhouette,structure,detail`, `--export-scad` | XY bounds from the canvas; connected solids from the silhouette mask's raster connectivity; genus from the silhouette mask's holes; per-role Z planes from the resolved heights |
| Corpus case, image mode, preset end to end | as above plus `--preset relief-0.4` | the same raster-derived expectations, with the preset's Z planes and B 0 bounds |

The through-hole pair is a control set, and the earlier draft had it backwards. A full rectangular backing
spans the canvas, so at B 1 it fills the donut's hole and the mesh closes to genus 0. Only B 0 can test a
through-hole.

The engraved row is the one that proves engraving cuts detail only, and it needs a location-aware check
rather than a plane-set argument. Z 0 is an expected bottom plane, so "a plane below 1.5" cannot by itself
prove over-engraving. The row asserts its full plane set `[0, 1.5, 2, 3]` with the global Z 0 retained, and
then samples the mesh at two known XY locations: inside the engraved recess the top surface is exactly
`B + S - D = 1.5`, and inside a structure ridge that the detail does not cover the top is exactly
`B + S + H = 3`. A recess floor below 1.5 at its own location is the over-engraving signal, and a ridge top
below 3 is the cut-ridge signal.

## Volume contract

Mesh volume is blocking, against this formula, which derives every term from the raster and the published
layer geometry rather than from the SCAD text:

- `V = B·A_canvas + S·A_silhouette + H·A_structure + D·A_detail` for raised detail.
- `V = B·A_canvas + S·A_silhouette + H·A_structure − D·A_detail` for engraved detail.

`A_canvas` is the canvas rectangle, which is what the backing spans. `A_silhouette`, `A_structure`, and
`A_detail` are the polygon areas of the published layer SVGs, computed by
`tests/fixtures/vector_map/corpus/metrics.py::polygon_area`. A role that is not selected contributes nothing,
and an empty role contributes zero.

The tolerance is the S1.4 locked relative tolerance `mesh_volume_rel = 1e-4` from `metrics.TOLERANCES`,
applied through `metrics.mesh_volume_ok`. It is not relaxed for this task. The 0.01 mm join overlap does not
perturb the formula: each taller solid spans 0.01 mm into the solid below it, and because S3.4 intersects
structure and detail into the silhouette in 2D, that overlap region is exactly contained in the lower solid,
so the union removes precisely the extra 0.01 mm the taller extrusion added. The naive sum is therefore exact
while containment holds. A case whose measured volume breaks containment has found a real CAD defect, and the
plan does not paper over it by widening the tolerance.

## Method

1. Build each case's layered bundle with the real CLI path, in process, one case at a time, into a work
   directory an OpenSCAD sandbox can read. Every CAD row is layered image mode with an external silhouette
   mask: the synthetic scenes pass `--layers silhouette,structure,detail` with their role maps, and the corpus
   rows pass `--input-kind image --mask <case>/mask.png --layers silhouette,structure,detail --export-scad`
   with structure and detail from the resolved Canny defaults, optionally with `--preset relief-0.4`. Record
   the argv, the exit code, the result JSON, and the manifest relief object.
2. Save the selected masks, the combined SVG, each published layer SVG, the manifest, and the SCAD source per
   case into the work directory, and hash them. Manifest hash verification is sprint step 7.
3. Render the SCAD with the real executable, capturing stdout, stderr, and its version. Parse the STL into
   unique vertices and triangles, then compute bounds, Z planes, connected solids, genus per solid, and mesh
   volume.
4. Derive each row's expectation from the raster: bounds and solids from the prepared silhouette mask, genus
   from its holes, per-role areas from the published layer SVGs, and the volume from the volume contract.
   Then sample the mesh at the row's known XY locations where the row names them, so the engraved row's recess
   floor and ridge top are read at their own coordinates rather than inferred from the global plane list.
5. Compare the measured mesh with the expectation. A mismatch is a failed case with its numbers recorded, not
   an aggregate decrement.
6. Emit one JSON evidence document keyed by case, holding versions, argv, output, the work directory, every
   artifact path with its hash, the manifest relief object, the expected geometry, and the measured geometry.
7. Write the report from that JSON, one section per case, with the exact reproduce and regeneration commands
   at the top.

The probe reuses `tests/test_vector_map_openscad.py` helpers (`_openscad`, `choose_work_dir`, `sandbox_error`,
`mesh_components`) so the executable discovery, the Flatpak home-directory rule, and the genus computation
have one implementation, and `tests/fixtures/vector_map/corpus/metrics.py` for `polygon_area`,
`mesh_volume`, `mesh_volume_ok`, and the locked tolerances.
